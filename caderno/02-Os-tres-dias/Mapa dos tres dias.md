# Mapa dos três dias

Você parte de uma rotina real e termina com uma solução testada.

```text
Dia 1
curso ToStudy → playbook → /brainstorming → PRD aprovado

Dia 2
Design OS → protótipo → /writing-plans → /executing-plans
→ MVP integrado funcionando

Dia 3
validação → reajustes → plano curto
→ /goal --plan → regressão → apresentação
(+ publicação, se você autorizar)
```

## O que cada dia entrega

| Dia | Trabalho | Você termina com |
|---|---|---|
| 1 | Contexto | Playbook validado + ideia + PRD **com mapa de ondas** |
| 2 | Geração | Protótipo + **onda 1** funcionando; onda 2+ listada, não apagada |
| 3 | Teste e entrega | Uso observado + refinamentos + apresentação + **por que** publicar |

O MVP precisa funcionar ao encerrar o Dia 2. O Dia 3 não é reserva para começar a implementação.

## Regras que valem nos três dias

- Uma fatia pequena: um usuário, uma dor, um fluxo principal.
- Alternar conteúdo e prática. Toda passagem termina em prova visível.
- Ambiente padrão: [[Orca]] + [[Claude e Claude Code]].
- Superpowers com os nomes reais: `/brainstorming`, `/writing-plans`, `/executing-plans`.
- `/goal --plan` só no Dia 3, só com o plano curto da validação.
- No Windows, o projeto fica em `~/founders-ai` no Ubuntu/WSL — nunca em `/mnt/c`.
- Integração só conta como real depois de uma ação testada. Demonstração precisa estar identificada.
- Nunca colocar senha, token ou chave em documento, tela ou Git. Segredos ficam no `.env` ignorado.
